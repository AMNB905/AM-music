试过两条弯路，记下来免得以后重踩：
- 0.6.63 把 APK 提交进公开仓库、客户端读 raw 直链 → 实测这套网络里 github.com 与
  raw.githubusercontent.com 大面积超时（同一刻 api.github.com 正常）。
- 于是 0.6.63/0.6.64 中间还试过「清单 + git blob 直链」，能用，但每版给仓库历史加 2.7MB。
- 最终确认：Release 资产走 `api.github.com/.../releases/assets/{id}` 会 302 到
  `release-assets.githubusercontent.com`，**这个域名是通的**（2.7MB 实测 2 秒）。
  真正连不上的是 `github.com/.../releases/download/...` 这个浏览器下载地址。

1) 版本来源：`api.github.com/repos/AMNB905/AM-music/releases/latest`（本仓库即公开仓库，匿名可读）。
   版本号取正文里的 `versionCode: NN` 标记（发版脚本写入，不靠 tag 猜），下载地址取 assets 里的 .apk。
   读不到再退自家 version.json；结果缓存 30 分钟（匿名 API 每 IP 每小时 60 次），
   但设置里手动点「检查更新」会强制刷新（forceRefresh），不受缓存影响。
2) 下载走资产 API（`Accept: application/octet-stream`）→ 302 → 预签名地址。
   代码里**绝不用** `browser_download_url`：那个地址是 github.com，这套网络里连不上。
   重定向那一步要去掉 Authorization（S3 同时见到 query 签名和 Bearer 会判冲突）。
3) 落装前三道闸：包名一致、versionCode 比当前大、签名证书 SHA-256 == 33a8be…，
   任一不过就删包并把原因写进弹窗。更新链路是唯一能把任意代码送进手机的入口。
4) 发版：`C:\toolchain\publish_release.ps1` 建 Release + 上传资产，需要 PAT 写权限。
   token 只在 PC 上用，**不进 APK**（正式包 UPDATE_TOKEN 恒为空，debug 构建才注入）。
5) 仓库里只留 `releases/CHANGELOG.md`，二进制全部由 Releases 托管。

本次改动（相对 0.6.60）
1) 识曲那句「音轨解不开（可能加密），换一条」拆成三句，各自带上具体原因：
   下载不来（HTTP 403 / 只拿到 0 字节）、下下来但端上解不开（编码不支持）、
   解出来了但曲库没对上。旧代码用一个 decodedAny 布尔值把三类失败糊成一句「可能加密」，
   用户据此做的判断（去加"下载原视频再抽音轨"）完全用不上——因为根因不在加密。
   实测（PC 侧复现 App 的签名请求）：抖音图文作品的 music/bgm 是普通 M4A，
   moov 在偏移 28（文件头）、单轨、sample entry 是 mp4a，容器里没有 sinf/enca；
   同一段音频按 8k/16bit/单声道 PCM 打 qq/api/recognize 能命中
   （INSONAMIA (Remix) / DJ白天 / 战场压制，offset 4.99s）。所以全链路是通的，
   「加密」这个说法不成立。
2) 图文作品（duration≈0）不再尝试 mix/mp4：服务端给的 fallbackUrl 是拿图片对象拼的，
   实测 HTTP 200 但 0 字节，白下两遍还拖慢。现在直接跳过，只认配乐音轨。
   这类链接取不到音轨时提示「图文作品：配乐没取下来 · 原因」。
3) ClipAudio 增加 fetch()（返回文件 + 失败原因），download() 保留原签名向下兼容。

本次改动（相对 0.6.49）：修「收起后整颗岛消失」
- 现象：0.6.49 触摸通了，但展开后收起时不是缩回胶囊，而是整颗不见。
- 根因：收起有两条独立动画——内容层（alpha/scale，withEndAction=finish）和整窗（root alpha 1→0）。
  两条都是 170ms 但触发顺序不固定：内容那条先结束时 finish 就去重挂窗口并把 root.alpha 掰回 1，
  紧接着整窗那条收尾又把 alpha 写回 0 —— 结果窗口还在、全透明，看起来就是「直接消失」。
- 修法：
  1. finish 里先 `root.animate().cancel()` 掐掉整窗淡出，再 `root.alpha = 1f`，然后才重挂；
     重挂完再把内容层 alpha/scale/translation 复位，最后再写一次 root.alpha=1f。
  2. 展开分支进入时也先 cancel + alpha=1f，兜住「上一次收起留下残影 → 展开了但看不见」。
  3. collapsed 日志补上 alpha 值，方便下次一眼确认是不是透明度问题。
- 其余沿用 0.6.49：灵动岛开启时 App 内隐藏状态栏（这是摄像头位置能点到触摸的前提）。

下面是 0.6.43 起累计的内容：

一、移除毛玻璃外观
- IslandAppearance 只剩 BLACK（纯黑）/ CUSTOM（自定义图片或视频）两档；
- 删掉窗口级模糊那一套（FLAG_BLUR_BEHIND + setBlurBehindRadius 及其 12+ 分支判断），
  设置页也不再按系统版本显示「低版本退化」的提示；
- 老数据兼容：prefs 里存过 "GLASS" 的，fromName() 会回落到 BLACK，不会崩也不会留个空档位。

二、修「无法展开」
根因：原来展开/收起是 ValueAnimator 每帧改 lp.width/height/x/y 再 updateViewLayout，
把窗口尺寸当成动画属性来跑。不少 ROM（尤其国产 ROM 的 overlay 窗口）会**接受但不执行**
这种高频 resize，或者干脆抛异常被 runCatching 吞掉 —— 状态已经切成「展开」，
窗口却还是胶囊大小，用户看到的就是「点了没反应 / 展不开」。

现在：
1. 新增 fillGeometry()：只算 lp 宽高位置、圆角、封面尺寸、左右留白，不碰 WindowManager；
2. applyGeometry()：整次切换**只调用一次** updateViewLayout，尺寸不做逐帧动画；
3. 动画只作用在内容层：展开时 content alpha 0→1 + scale 0.92→1（pivot 在锚点），
   收起时 content 缩到 0.94 并连整窗 alpha 一起淡出（170ms），动画结束后才收窗口，
   避免中途露出「满屏宽的黑色卡片」；
4. 自愈：updateViewLayout 失败、或下一帧量出 root.width/height 与 lp 不一致（说明 ROM
   没执行），就 removeView + addView 重挂一次（每个状态只救一次，避免死循环）；
5. 收起动画加了 400ms 兜底，防止动画被打断后 animating 永久卡 true（卡住会表现为
   后续点击全部无效）；
6. 定位/滑块热更新统一走 applyGeometry()，不再各自维护一套坐标公式。

自研灵动岛（0.6.42 起，源码在这一版里）
1. service/DynamicIslandService.kt：WindowManager + TYPE_APPLICATION_OVERLAY。
   - 收起态胶囊 = [封面 20dp | 左右留白 | 摄像头黑点 | 频谱 20dp]，
     高 = 锚点 + 22dp，宽 = max(设定长度, 56 + 锚点)，圆角 = 高的一半；
   - 展开态：宽 = 屏宽 - 16dp，高 = 锚点 + 156dp，顶边钉在锚点；
     64dp 封面 + 歌名/歌手 + 可拖 SeekBar（28dp 高，防把三键顶出卡片）+ m:ss 时间 + 三键；
     3 秒无操作自动收起，点卡片外（FLAG_WATCH_OUTSIDE_TOUCH）也收起；
   - 内边距只加在内容层（加在 root 会把自定义背景挤成不满铺、展开还会裁掉底部）；
   - 数据源是同进程 AppContainer：playbackManager.state 每 200ms 轮询，封面走
     coverCache.ensure() 再采样解码，换歌才重载；
   - 点封面/歌名 → IslandNavigator.requestOpenPlayer()：App 在前台走注入的
     NavController lambda，不在前台就拉起 MainActivity 并交一次性 pending；
   - 横屏自动隐藏；进程被回收后回前台由 MainActivity 补启（判 isRunning）。
2. 自定义背景：ACTION_OPEN_DOCUMENT 选 content:// 图片或视频
   （takePersistableUriPermission 持久化），按 getType() 前缀 video/ 判类型；
   图片 ImageView(CENTER_CROP) 采样解码，视频第二个 ExoPlayer（静音、REPEAT_MODE_ONE）
   挂 TextureView，上面压 0x8C 黑 scrim 保白字；没选素材回退纯黑。
3. 定位模式：单独一颗黑点，拖动对齐挖孔，轻点完成并落盘百分比；
   窗口用 FLAG_LAYOUT_IN_SCREEN，y=0 对齐物理屏幕顶。
4. 设置页「灵动岛」分组：开关（缺权限跳 SYSTEM_ALERT_WINDOW 授权页）、外观两选、
   选图片/选视频/清除、锚点直径 8–40dp / 胶囊长度 60–180dp / 锚点 X·Y 百分比滑块、
   拖动定位；改设置只写盘 + 给服务发动作，服务没开就不发。
5. ui/island/SpectrumBarView.kt：12 根圆角细柱自绘，播放中用正弦 + 随机叠加的模拟频谱
   驱动（不做真实 AudioRecord，省电也不占录音权限）。
6. 系统媒体岛开关（0.6.41 起）：SwitchableMediaNotificationProvider 在开关打开时改发
   不带 MediaStyle、不挂 sessionToken 的普通前台通知，ROM 就不会再顶出自己的媒体岛；
   设置页「播放」组「系统媒体岛」：跟随系统 / 关闭。

AndroidManifest：SYSTEM_ALERT_WINDOW + .service.DynamicIslandService。

为什么是普通 started service 而不是前台服务：不想再挂常驻通知、也不想多申
FOREGROUND_SERVICE_SPECIAL_USE。代价是进程被回收后岛会消失，已用「回前台补启」兜住。
要改成前台服务只需在 service 里 startForeground。
